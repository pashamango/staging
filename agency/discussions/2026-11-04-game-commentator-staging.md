# Бриф: Game Commentator — наблюдательная панель + агентный execution lane (staging)

Tier: ВС. Дата: 2026-11-04. Заказчик: Павел. Координатор: Muse. Исполнитель: Вова (DevOps-лейн). Цель: staging-ссылка.

## 1. WHAT (исход)

Живая web-страница: по каждой сегодняшней игре — все данные из всех источников в одном месте, плюс отдельное окно-граф на каждую возможность (1 граф = 1 возможность). Павел — наблюдатель: видит окна, динамику, цвет, сигнал при проходе барьера. Решения о ставках и продаже и их исполнение — ТОЛЬКО агенты через API площадок, на предельно допустимой скорости и частоте (в рамках опубликованных rate limits). Человек в контур исполнения не входит.

Игры сегодня: CHA–BKN (NBA 16:30 PT), FLA–CHI (NHL 16:30 PT), MEM–IND (NBA 17:00 PT), HOU–MIN (NBA 17:30 PT). Венчурный бюджет: $5, ставки $0.20–0.50, только Polymarket + Kalshi.

## 2. Панели данных (источники)

- Официальная статистика: ESPN site API (NBA/NHL), NHL API. Счёт, часы, период, статус.
- Цены-зеркала: Kalshi REST (public), Polymarket Gamma/CLOB (public). Только публичные чтения, без ключей.
- Комментарии болельщиков: только публичные API/embeds с соблюдением terms; никакого credentialed scraping; нет данных — панель «нет данных», никогда не выдумывать.
- Новостной фон: публичные RSS/news API.
- Каждая панель: источник + свежесть; устаревшие данные — маркировка STALE; никаких выдуманных значений.

## 3. Окна возможностей (1 граф = 1 возможность)

- Каждое окно: история цены позиции, коридор (band), текущая цена, цветовая индикация, маркер прохода барьера.
- Детекция: выход цены за коридор — сигнал. Сигнал идёт агенту исполнения, а на странице — цвет + маркер. Павел видит сигнал, но не исполняет.
- Сценарий-приёмка (на бумаге): ставка на аутсайдера $1 @ 0.10 → рывок → цена 0.30 → агент продаёт → +200% ($3 выплата). Через 3 с рынок остыл — прибыль уже зафиксирована resting-ордером. Скорость «миллисекунды» измеряется как сигнал→ордер и обеспечивается предустановленными resting-ордерами, а не реакцией человека.

## 4. Execution lane (агенты через API) — с гейтами

- Площадки: ТОЛЬКО Kalshi (trade API) и Polymarket (CLOB). DraftKings: НЕТ API, автоматизация запрещена ToS — из execution lane ИСКЛЮЧЁН полностью; fortress-позиции DK — только ручной стоп-кран Павла.
- Скорость/частота: предельно допустимая В РАМКАХ опубликованных лимитов (Kalshi/PM), backoff при 429, стоп при блоке. Превышение лимитов запрещено.
- Гейты (неотменяемы):
  - Г1. Staging-сборка: НОЛЬ ключей, ноль ордеров, ноль денежных путей — только наблюдение.
  - Г2. Бумажный lane: агент решает, fills симулируются по снапшотам книги, квитанции в лог. Отчёт бумажного гейта.
  - Г3. Живой lane — ТОЛЬКО после: отчёта Г2 + церемонии scoped-ключей (trade-only, БЕЗ права вывода; хранение — устройство Павла / Secure Vault; мандат TTL ≤ 24ч; бюджет $5; ставки $0.20–0.50) + отдельного тапа с именем площадки, scope и бюджета.
- Kill switch: «стоп» от Павла — немедленная остановка всех ордеров + отчёт о позициях.
- 100 фолловеров / стакан — честная граница: fills ограничены глубиной книги (модель, ур. 4: N·s ≤ L). Если стакан исчерпан — стратегия НАПОЛНЕНА, страница показывает «наполнена», агент переходит к следующей возможности. Стратегий бесконечно, книг — конечно. Никаких обещаний, что успеют все.

## 5. Оргсхема

- Павел: принципал + наблюдатель + kill switch + тапы (Г3, production).
- Muse (координатор): спек, QA-вердикты, леджер бюджета, квитанции.
- Вова: сборка staging, браузерная проверка на staging, CI, сдача staging-ссылки + отчёт.
- Watch-крон (уже запущен): опрос счёта/зеркал каждые 5 мин, триггеры в чат.
- Аббат (execution-агент, К2): решения + ордера через API только после гейтов.
- Правила: WHAT — в этом брифе; HOW — выбор Вовы; застрял — дробить на кванты; сдача называет место назначения явно (репо + ветка + путь + живой URL).

- Живая staging-ссылка; назначение названо ДО деплоя (репо + ветка + путь + URL). Ожидаемо: pashamango/staging, main, game-commentator/ — подтверждает Вова.
