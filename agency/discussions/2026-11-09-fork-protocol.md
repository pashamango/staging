# Протокол форков по средам (тред)

Дата открытия: 2026-11-09. Статус: открыт, ждёт решения Павла по Q1.
Вотчер: gemini@darwin — первичный триаж и маршрутизация.
Канон: Forgejo `https://darwin.tail94aa6c.ts.net:3001/pasha/agency`, main `7100e41`.
Дизайн: `discussions/2026-11-09-consolidation-design.md` §5; мануал: `manuals/09_local_support_and_forks.md` §4.

## Вопрос (WHAT)

Каждая среда делает свой форк agency.git, меняет его в реальном времени;
новые функции автоматически становятся доступны остальным для добровольного
обновления (повеление Павла 10:45 PT 2026-11-09). Нужны: протокол мержа
в канон и арбитр мержа — предлагается, не решается этим тредом.

## Предложение (из дизайна §5, черновик для тапа)

1. Каждая проверенная среда (darwin, wolfram, d007, muse-vm, simular box)
   ведёт свой форк; изменения — в форк в реальном времени, без ожидания канона.
   Форк без записи в `REGISTRY.md` — невидимый: его обновления не подхватываются.
2. Новая функция публикуется как предложение в канон: тред `[fork-update]`
   в `discussions/` (WHAT, diff-ссылка, среда-источник). Остальные среды
   забирают обновление pull'ом в свой форк — добровольно, в своём ритме.
3. Канон ведёт учёт: какая функция из какого форка доступна, кто забрал,
   кто отказался и почему (отказ — тоже запись, а не молчание).
4. Функция, забранная ≥2 средами и прожившая ≥2 недель без REWORK, —
   кандидат в канон.
5. Критерии мержа (общие для любого варианта арбитра): WHAT + acceptance
   выполнены; staging-доказательство приложено; нет секретов в diff'е;
   нет конфликта с конституцией; dedup-проверка пройдена;
   business-model horizon указан, если мерж — проект/инициатива, а не правка текста.
6. Конфликт мержа — дискуссия `[merge-conflict]` с двумя позициями;
   до решения арбитра обе версии живут в своих форках, канон не трогается.

## Варианты арбитра мержа (выбрать тапом — Q1 дизайна)

- **A — координатор как арбитр.** Muse-координатор решает мерж в канон;
  Павел тапает только конфликты, изменения конституции и спорные мержи.
  Плюс: быстро, один ответственный. Минус: bottleneck возвращается к Muse (квота).
- **B — совет лейнов + вето Павла.** Мерж решает совет представителей лейнов
  (по одному от agy, codex, gemini@darwin, antigravity, vova) простым большинством;
  Павел — вето одним словом и арбитр при равенстве. Плюс: децентрализация.
  Минус: совет надо собирать; равенство голосов — частый случай при пяти участниках.
- **C — только Павел.** Каждый мерж в канон — тап Павла (да/нет, как утренняя
  приёмка по Ритму #1). Плюс: максимальная чистота канона. Минус: bottleneck
  внимания Павла; при 20,000 сотрудников не масштабируется даже в теории.
- Гибрид (на усмотрение Павла): A для текстовых правок, C для конституции.
